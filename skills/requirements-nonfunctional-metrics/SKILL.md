# 非機能要件の測定指標

## Overview
性能・容量・可用性・法令対応・プライバシーの要件に数値、前提条件、測定方法を与えます。

## When to Use
- 要件フェーズで非機能指標を定義・レビューするとき。
- 対象外：純粋な機能要件、実装・運用工程の具体的な調整。

## Core Process
- 性能をページ P95 ≤ ?ms、API P95 ≤ ?ms @ 同時実行数 ?、一括処理 ≤ ?分/1万件のように数値化し、ブラウザー/ゲートウェイ/DB などの測定点とデータ量を示します。
- 日次利用者数、最大 QPS、1 レコードのサイズ、年間増分、保存年数から、ストレージとバックアップ規模を計算式で算出します。「十分な容量」で済ませません。
- 可用性 99.5 / 99.9% などの目標、月間許容停止時間、読み取り専用化・待ち行列などの縮退対象と費用を示します。
- 個人・機微データ、根拠法令、保存・削除要件、越境の有無を記載します。未確定事項は法務確認待ちとして阻害する範囲を示します。
- 各要件に負荷試験スクリプト、監視画面、監査レポートなどの受入手段を定めます。測定手段がない要件は未定義として扱います。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 性能は十分速ければよい | 数値・負荷条件・測定点がなければ判定できません。 |
| 容量は余裕を持たせる | データ増分・保存期間と計算式が必要です。 |
| 法令や保存期間は後で確認する | 未確定事項とその影響を明示し、確認担当へつなぎます。 |

## Red Flags
- P95 / P99 に負荷条件や測定点がありません。
- 容量の計算式、許容停止時間、縮退方式がありません。
- 機微データの保存・削除・越境が未確認で、受入手段もありません。
