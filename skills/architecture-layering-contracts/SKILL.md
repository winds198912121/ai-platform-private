# アーキテクチャのレイヤー・契約・固定方針

## Overview
レイヤー構成、契約、変更費用の大きな決定を明文化します。いずれかが欠けると、後続モジュールが別々の解釈で実装されます。

## When to Use
- アーキテクチャ設計書、モジュール境界、API 契約、データモデルの作成・レビューに使用します。
- 変更費用の大きな決定と現時点で変更しない理由を記録するときに使用します。
- 対象外：単一モジュール内部の設計、クラス・メソッド単位のリファクタリング。

## Core Process
- 各項目を設計書の必須項目として扱います。
- core/domain/service/api などのソースレイヤー一覧、下位から上位へ依存しない方向、各層の責務と禁止事項を記載します。プラットフォームは ARC-01 の一覧を解析し、解析不可時は既定値とその出所をログに記録します。
- データモデルはフィールド名、型、nullable、既定値、一意制約・索引を定義します。金額は最小単位の整数または decimal、時刻は UTC ISO-8601 とします。
- API はメソッド、パス、要求フィールド、状態コード、エラーコード表を定義し、エラーを自由文ではなく列挙値にします。
- 外部依存ごとに用途、呼び出し頻度、障害時の縮退、タイムアウト、再試行上限を登録します。
- 技術スタック、ストレージ、テナントモデル、認証・認可モデルなど、変更費用の大きな決定と変更しない理由を明記します。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| レイヤーは実装中に自然に決まる | 配置は設計書に従います。未記載では既定レイヤーへ配置されます。 |
| API フィールドやエラーは後で追加する | 呼び出し側全体に影響するため契約として確定します。 |
| 金額は float でもよい | 金額・照合には整数または decimal、時刻には UTC ISO-8601 を使います。 |
| 依存のタイムアウトや再試行は設計不要 | 上限のない依存は呼び出し連鎖全体を停止させます。 |
| 大きな方針は必要になったら変更する | 現時点で維持する判断にも、選択理由と変更費用の記録が必要です。 |

## Red Flags
- ディレクトリだけがあり、責務と禁止事項がありません。
- データモデルに型・nullable・既定値・金額・時刻の表現がありません。
- エラーが自由文だけで、列挙表がありません。
- 外部依存に用途・頻度・縮退・タイムアウト・再試行上限がありません。
- 固定方針と技術スタック・ストレージ・テナント・認証方式の選択理由がありません。

## Verification
- [ ] ソースレイヤー一覧、依存方向、責務、禁止事項を確認しました。
- [ ] フィールド単位の定義と金額・時刻の表現が揃っています。
- [ ] API のメソッド、パス、要求、状態コード、列挙エラーが揃っています。
- [ ] 全外部依存の用途・頻度・縮退・タイムアウト・再試行上限を確認しました。
- [ ] 変更費用の大きな決定と現時点で維持する理由を記録しています。
