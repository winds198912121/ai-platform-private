# テストケース設計

## Overview
同値分割、境界、組み合わせ、状態遷移、異常、データの再現性、リスク優先度を使って検証可能なケースを設計します。

## When to Use
- 要件・API・モジュールの入力検証、複数引数、状態遷移、異常・並行・重複送信のテストを設計するとき。
- 対象外：カバレッジ表と終了条件（testing-coverage-matrix）、性能・安全性（testing-perf-and-security）、コードレビューのみ。

## Core Process
- 入力ごとに有効・無効の同値クラスと代表値を列挙し、各境界の上限−1、上限、上限＋1 を検証します。
- 組み合わせが多い場合は全順列ではなく pairwise を使い、意図的に除外する組み合わせと理由を記録します。
- 状態×イベントの表を作り、合法・不正の両遷移を検証します。不正な遷移は拒否され、状態が変わらないことを確認します。
- タイムアウト、重複要求、並行書き込み、外部依存のタイムアウト・エラーコード・空応答も正常系と同等に扱います。
- データの作成元、作成担当、実行後に残すか、後処理を明示し、繰り返して同じ結果を得られるようにします。
- P0（主要経路を阻害）、P1（利用体験へ影響）、P2（境界）を付け、リスク別の終了条件を設定します。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 正常系が通れば十分 | 境界・不正状態・異常依存・重複・並行を同等に検証します。 |
| 全組み合わせを列挙するしかない | pairwise と除外理由で規模を管理します。 |
| テストデータは適当に残してよい | 作成と後処理を定義し、繰り返し実行の一致を確保します。 |

## Red Flags
- 境界・無効入力・不正遷移が未検証です。
- 並行・重複・依存障害を除外しています。
- データの後処理と再現性、リスク優先度、終了条件がありません。
