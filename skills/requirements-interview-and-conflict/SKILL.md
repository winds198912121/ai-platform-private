# 関係者ヒアリングと要件の対立整理

## Overview
関係者、判断権限、ヒアリングの根拠、対立、変更、仮定とリスクを追跡できる形で記録します。

## When to Use
- 要件フェーズでの関係者ヒアリング、対立の登録、要件変更に使用します。
- 対象外：要件が確定し、関係者の相違がない実装工程。

## Core Process
- 開始前に、関係者の役割・関心事項・範囲/予算/公開の決定権限・参加方法と頻度を一覧化します。
- ヒアリングは質問→回答→結論/未決事項で記録します。未決事項には担当者と期限を付け、発言者・日時・原文を示します。「利用者が言った」だけを結論にしません。
- 対立点、各者の要求、影響範囲、候補案と費用、最終決定者を登録します。却下案も記録し、同じ議論の再開を防ぎます。
- 変更番号・理由・影響する要件/工数/日程・承認者を同じ変更表で管理し、口頭だけの変更は認めません。
- 仮定とリスクを分けます。仮定には誤り時の影響と検証方法、リスクには確率×影響、緩和策、発動条件を記載します。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 発言者を残さなくても意味は分かる | 誰がいつ何を述べたかという根拠が必要です。 |
| 対立は実装者が判断すればよい | 候補と費用を示し、権限のある関係者が裁定します。 |
| 口頭の変更は後で記録する | 変更番号、影響、承認者の記録を先に残します。 |

## Red Flags
- 関係者と決定権限が不明です。
- 未決事項に担当・期限がなく、発言の出所を追跡できません。
- 却下案、変更の承認、仮定の検証、リスクの発動条件が欠けています。
