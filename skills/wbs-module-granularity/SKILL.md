# WBS モジュールの粒度と受入条件

## Overview
1 人が 1 回の作業で実装でき、単体テストを独立実行できる最小単位へ分解し、実行可能な受入条件と依存を定義します。

## When to Use
- 要件・設計から Task を分解し、受入条件、追加分割の要否、粒度と依存をレビューするとき。
- 対象外：三点見積もり、クリティカルパス、外部依存と日程（wbs-estimate-and-dependencies）。

## Core Process
- 1 モジュールは 1 人が 1 回で実装し、独立して単体テストできる最小単位とします。共有ロジックは先に共通モジュールとして抽出します。
- 全 Task に入力→期待結果の実行可能な acceptance を記載し、境界・エラーも含めます。「画面を完成する」だけで済ませません。
- Task の先後関係と並行可否を明示します。依存先が未完了のまま依存する Task を完了扱いにしません。
- 各モジュールのレイヤー、成果ファイルパス、テストパスを記載します。
- 測定可能な変更前後の指標がない「リファクタリング」「最適化」を Task にしません。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 大きくまとめれば管理しやすい | 独立実装・独立テストできる粒度にします。 |
| 画面完成と書けば受入できる | 入力・期待値・境界・エラーの具体的な判定が必要です。 |
| 依存先は後でつなぐ | 依存の未完了を隠して完了扱いにできません。 |

## Red Flags
- 1 回で実装できず、他モジュールなしではテストできません。
- acceptance、依存順序、成果物・テストのパスがありません。
- 指標のない最適化や再構成だけが Task になっています。
