# 情報構造と画面の状態設計

## Overview
情報構造、空・読み込み中・成功・失敗の 4 状態、実装可能な操作規則、確定文言、アクセシビリティを定義します。

## When to Use
- UX フェーズで情報構造、4 状態、インタラクションを作成・レビューするとき。
- 対象外：ビジュアルスタイルとブランドの方向性の検討。

## Core Process
- 画面/領域/コントロールの 3 階層を IA-NN の安定した番号で記載し、主要経路と例外経路を示します。
- 各画面に空、読み込み中、成功、失敗を定義し、失敗文言と次の操作まで記載します。成功画面だけを設計しません。
- フィールドの検証時機（フォーカス離脱/送信）、ボタン無効化条件、フィールドへのエラー表示をフロントエンド実装可能な粒度で定義します。
- 最終的な日本語・English の文言、最大長、切り詰め規則を示し、「ここに説明を置く」などの仮置きにしません。
- キーボードで到達可能、フォーカスが可視、入力に label があり、色だけに情報を依存しない設計とします。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 成功画面だけあれば十分 | 空・読み込み中・失敗とその次の操作も必要です。 |
| 文言は実装者が埋める | 最終文言、長さ、切り詰め方を設計します。 |
| 検証の詳細は実装任せでよい | 検証時機・無効化・フィールドへのエラー表示まで定義します。 |

## Red Flags
- 画面階層と番号、例外経路、4 状態がありません。
- 仮文言、未定義の最大長、操作の検証条件の不足があります。
- キーボード操作・label・可視フォーカスがありません。
