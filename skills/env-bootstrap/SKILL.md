# 実行環境の自動準備

## Overview
実行環境が実際に利用可能か確認し、不足するランタイム・ツール・システム依存をインストール・設定して再検出します。環境不足を成功したように扱いません。

## When to Use
- JDK、python3、パッケージ管理、DB、ディレクトリ、ポートが不足して開始できないとき。
- JAVA_HOME / PATH が不適切、またはツールの代替スタブだけが見つかるとき。
- 対象外：成果物のコード依存の選定、別途承認が必要な本番・共有基盤の変更。

## Core Process
- 不足する実行環境は brew install、apt-get install、公式インストーラーなどで準備し、設定後に再検出して続行します。未準備のまま待機したり、準備済みと偽ったりしません。
- JAVA_HOME → PATH → パッケージ管理の keg の順で検出します。macOS の /usr/bin/javac や /usr/bin/python3 はスタブの場合があるため、実際の -version 出力で確認します。
- 既存環境を変更せず不足分だけを導入し、インストールを冪等にします。コマンドにはタイムアウトを設けます。
- JAVA_HOME / PATH、UTF-8、UTC、必要ディレクトリとポートも確認します。keg-only JDK のパスは明示します。
- 導入できない場合は、実行したコマンド、終了コード、不足項目、利用者が次に行う手順を報告します。スタブ、模擬データ、別ランタイムへの縮退で失敗を隠しません。
- 自動準備の対象は実行環境です。コードのライブラリ・フレームワークは引き続き設計書の登録内容に従います。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 環境がないので最初に利用者へ質問する | 自動準備可能な範囲では検出・導入・再検出を行い、失敗時に終了コードとともに報告します。 |
| which java が返れば利用できる | 実際のバージョン出力でスタブではないことを確認します。 |
| 環境確認は機能実装後でよい | 実行環境を検証できるまで成果物の実行可能性は証明できません。 |
| 実行できなければ mock へ切り替える | 模擬実行は実環境の代替にならず、環境不足を成功として扱えません。 |
| ツールのインストールだけで完了 | パス、文字コード、タイムゾーン、ディレクトリ、ポートまで検証します。 |

## Red Flags
- 検出前に環境不足として作業を止めます。
- which や実行権限だけで判定しています。
- スタブや模擬データで環境不足を回避しています。
- 既存ツールを重複導入するか、タイムアウトがありません。
- keg-only JDK の JAVA_HOME が明示されていません。

## Verification
- [ ] 実ランタイムの -version 出力を記録しました。
- [ ] 不足コンポーネントを導入し、再検出で変化を確認しました。
- [ ] JAVA_HOME / PATH、UTF-8、UTC、必要ディレクトリ・ポートを再確認しました。
- [ ] インストールは冪等で、タイムアウトがあります。
- [ ] 最終的な失敗報告にはコマンド・終了コード・不足項目・次の手順があります。
