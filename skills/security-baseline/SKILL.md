# 共通セキュリティ基準（全ステージ）

## Overview
技術スタックに依存せず、既定拒否、入力の不信頼、最小権限、データ最小化、秘密情報の分離を全ステージで確認します。

## When to Use
- 全ステージの設計、実装、レビュー、引き渡しに使用します。
- 権限、外部入力、DB アカウント、トークン、ログ、エクスポートを変更するとき。
- 対象外：特定フレームワーク専用の強化策、成果物と無関係な外部システム運用。

## Core Process
- 明示的に許可されていないアクセスは拒否し、サーバーで権限を判定します。画面のボタン非表示では代替できません。
- ユーザー、外部サービス、ファイル、URL 由来の入力を入口で型・長さ・範囲・許可リストにより検証し、利用時にも境界を確認します。
- プロセス、DB、サービスアカウント、トークンには必要最小限の権限だけを与え、管理者アカウントでアプリを稼働させません。
- 必要なデータだけを収集し、用途と保存期間を定めます。ログ・エラー画面・出力ファイルにパスワード、トークン、公的識別番号などを含めません。
- 秘密情報は環境変数または秘密管理から読み、コードやイメージに含めません。漏えい時は直ちに更新し、記録します。
- 依存のバージョンを固定し、既知の脆弱性を定期確認します。出所不明のパッケージや postinstall などのビルドスクリプトは禁止します。
- 権限・設定・データ削除・公開などの重要変更を、誰がいつ何を変えたか追跡可能にします。
- 引き渡し前に、漏えいや誤動作の最悪の影響と、成果物に実装した防御を確認します。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 画面でボタンを隠している | サーバーで未認可要求を実際に拒否する必要があります。 |
| 社内サービスの入力なので信頼できる | すべての入口で検証し、利用時にも境界を再確認します。 |
| まず管理者で動かし、後で権限を絞る | 最小権限は引き渡し条件です。管理者での稼働自体が脆弱性になります。 |
| 調査のため機微情報をログへ出す | マスキングや相関 ID を使用し、秘密情報を記録しません。 |
| ローカル実行用に秘密情報を設定ファイルへ書く | 環境変数か秘密管理を使用し、コード・イメージへ入った秘密は更新します。 |

## Red Flags
- 認可が画面側だけにある、またはサーバーで既定許可しています。
- 未検証の外部データが業務処理やクエリへ渡されます。
- アカウント・トークン・プロセスが過大な権限を使用します。
- コード、イメージ、サンプルに実際の秘密情報があります。
- 依存バージョンが未固定か、出所不明のパッケージ・スクリプトがあります。

## Verification
- [ ] 未認可要求が拒否される再現可能な要求・応答の証拠があります。
- [ ] 全入口の型・長さ・範囲・許可リスト検証と、利用時の再確認があります。
- [ ] 実行アカウントとトークンが最小権限で、管理者を使っていません。
- [ ] ログ・エラー・出力ファイルにパスワード、トークン、公的識別番号がありません。
- [ ] リポジトリとイメージに実際の秘密がなく、依存を固定して脆弱性確認できます。
- [ ] 権限・設定・削除・公開の重要変更を監査できます。
