# 運用費用と容量の計画

## Overview
資源台帳、拡張条件、費用異常、四半期の改善、機能公開による費用増分、実請求との照合を管理します。

## When to Use
- インスタンス・ストレージ・帯域・外部 API の費用集計、容量上限と拡張、費用異常、新要件の費用評価。
- 対象外：監視・ログ（operations-monitoring-runbook）、バックアップ・復旧（operations-backup-and-restore）。容量のしきい値は監視方針と一致させます。

## Core Process
- 資源ごとの仕様、単価、月間使用量と傾向を台帳へ記録し、増加が速い上位 3 項目を四半期ごとに再計算します。前期の結論を流用しません。
- CPU、メモリ、ディスク、接続数、キュー長の警告値と拡張操作、実行者、効果が出るまでの時間を定義し、監視のしきい値と揃えます。
- 前日・前週比が上限を超えたら警告します。外部 API に割当上限と縮退経路を設け、上限超過時のシステム応答と利用者の表示を定義します。
- 四半期ごとに廃止可能な資源、縮小できるインスタンス、統合できるジョブを列挙し、節約見込み額とリスクを示します。金額のない項目を改善として数えません。
- 公開前に予想 QPS × 単価と保存量の増分から費用を見積もります。しきい値超過時は追加費用、得られる価値、実施しない影響を示します。
- 台帳・警告・実請求を照合し、単価と月間使用量が請求書に対応することを確認します。しきい値を超える差を説明します。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 前期と同じ上位費用を追えばよい | 増加率の上位 3 項目を四半期ごとに再計算します。 |
| 縮退は内部処理なので表示の定義は不要 | 超過時に返す内容と利用者に見える状態を定義します。 |
| 改善案は節約額なしで列挙してよい | 金額とリスクを示し、実請求へ照合します。 |

## Red Flags
- 単価・使用量・増加傾向の台帳がありません。
- 拡張の担当と所要時間、割当超過時の応答が未定義です。
- 節約額のない改善案、公開前の増分評価不足、実請求との未説明差があります。
