# バックアップと復旧

## Overview
データセット別の保護、業務上の RPO/RTO、実行可能な復旧、独立環境での演習、実際の読み取り検証、保管と削除を定義します。

## When to Use
- バックアップ方針、RPO/RTO、復旧スクリプト、復旧演習、期限切れデータの保存・削除の設計とレビュー。
- 対象外：監視・アラート・ログ（operations-monitoring-runbook）、容量・費用（operations-cost-and-capacity）。

## Core Process
- データセットごとに全量/増分の頻度、日/週/月の保存期間、遠隔地・別アカウントの保存先、暗号化と権限を 1 行ずつ記載します。「すべて毎日」の一括表現にしません。
- 許容損失量の RPO と復旧時間の RTO を定めます。現状との差には数値と解消時期を記載し、現状を要件へ書き換えません。
- 復旧は実行スクリプトまたは番号付き手順にし、権限、依存の起動順、外部サービスを再開できる段階を明示します。「バックアップから戻す」だけでは不十分です。
- 四半期に 1 回以上、事前の基準値を記録してから独立環境へ実際に復旧し、所要時間、失敗箇所、修正項目を残します。復旧先は本番とストレージを共有しません。
- 定期的にバックアップを実際に読み、チェックサムを検証します。ジョブ失敗とサイズ異常を警告し、成功ログだけを検証として扱いません。
- 保存期限を過ぎたデータを法令要件に従い削除します。事前のバックアップ確認と不可逆操作の承認を残し、削除前後を記録します。
- 演習の失敗は手順・方針・改善一覧へ反映し、レポートの備考だけで済ませません。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 全データを毎日バックアップするで十分 | データセットごとに頻度・保存・権限を定義します。 |
| 成功ログがあるので復旧できる | 実際の読み取り・チェックサムと独立環境への復旧が必要です。 |
| 現状の復旧時間を RTO にする | 業務要件との数値差と解消計画を示します。 |
| 演習の失敗は備考へ残せばよい | 手順、方針、改善作業へ反映し、再確認します。 |

## Red Flags
- データセット別の方針、RPO/RTO と現状の差がありません。
- 復旧手順の権限・順序・再開地点が不明です。
- 演習先が本番と共有され、実読み取り検証がありません。
- 削除承認・前後記録、演習結果の改善反映がありません。
