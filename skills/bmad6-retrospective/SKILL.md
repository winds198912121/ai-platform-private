# BMAD v6 · 振り返り（retrospective）

## Overview
証跡（差戻し記録・失敗ログ・起票された曖昧点）から教訓を 1 件ずつ取り出し、人が承認したものだけを案件専用スキルに書き戻して次のスライスに効かせます。（BMAD Method v6 本家ワークフローの手順を本プラットフォーム向けに要約したもの。原典：docs.bmad-method.org）

## When to Use
- Epic・スライスの完了時。
- 差戻しやテスト失敗が同じ原因で繰り返されたとき。
- 対象外：本番障害の初動対応（障害対応スキルを使う）。

## Core Process
1. 差戻し・失敗・曖昧点の記録を集め、原因ごとにまとめる。
2. 1 原因につき「教訓」を 1 件書く（何をすべきか / 何を禁止するか）。
3. 教訓を人がレビューし、承認したものだけを案件専用スキルへ追記する。
4. 次のスライスでその教訓が効いたかを確認する。

## Common Rationalizations
| 言い訳 | 事実 |
|---|---|
| 「失敗は直したので終わり」 | 原因をスキルに戻さないと同じ失敗が次のスライスで再発する。 |
| 「教訓は AI が勝手に追記すればよい」 | 未承認の規則追加は矛盾を生む。人の承認を必須にする。 |

## Red Flags
- 差戻しが続いているのに教訓が 1 件も無い。
- 教訓が「気をつける」など行動に落ちていない。
- 承認されていない規則がスキルに入っている。

## Verification
- [ ] 差戻し・失敗ごとに教訓の有無が判断されている。
- [ ] 教訓が具体的な規則（すべき / 禁止）になっている。
- [ ] 承認済みの教訓だけがスキルに書き戻されている。
- [ ] 次のスライスで効果を確認した記録がある。
