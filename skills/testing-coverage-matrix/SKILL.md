# 要件カバレッジ表とテスト終了条件

## Overview
要件とテストの対応、単体・結合・E2E の役割、実行方法、判定、失敗調査、環境初期化と公開条件を定義します。

## When to Use
- テスト計画・カバレッジ表・テスト層・実行コマンド・成功条件・失敗特定・終了条件を作成するとき。
- 対象外：具体的な単体テストコード、デプロイ・パイプライン・ロールバック計画。

## Core Process
- 要件番号×テストケース番号の表を作り、未網羅の箇所には未実施の費用・影響と理由を記載します。
- 単体は純粋ロジック、結合はモジュール間契約、E2E は主要経路と重要な異常を担当し、各層に実行コマンドと成功条件を付けます。
- 各ケースに前提データ、手順、検証可能な期待結果、失敗時に参照するログ・レコードを示します。
- データ生成スクリプト、クリーンアップ、冪等性により環境とデータを初期化でき、繰り返し同じ結果を得られるようにします。
- 必ず成功すべきケースと、既知の問題を許容できるケースを区別し、後者には追跡チケット番号を付けます。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| テストが多ければ網羅している | 要件番号とケース番号の対応で確認します。 |
| 実行方法は担当者が知っている | 各層のコマンド・条件・失敗調査先を文書化します。 |
| 軽微な問題はチケットなしで公開する | 終了条件と追跡番号で許容範囲を明示します。 |

## Red Flags
- 要件とケースが対応せず、未網羅の理由がありません。
- 手順・期待値・実行コマンド・調査先が不足しています。
- 環境を戻せず、既知不具合の許容条件・チケットがありません。
