# リリースとロールバック

## Overview
環境、検証可能な公開手順、戻し方、設定と秘密情報、変更時間帯、スモークテストをリリースごとに定義します。

## When to Use
- 公開計画、環境表、設定の出所、ロールバック条件・手順、変更時間帯、スモーク項目を作成するとき。
- 対象外：パイプライン・成果物昇格・カナリア比率（deployment-pipeline-and-canary）、CI スクリプトの構文調査。

## Core Process
- 環境名、ドメイン・入口、DB、依存サービス、環境変数・設定管理などの設定元を一覧にします。
- 順序付きの公開手順を作り、各段階に検証コマンドと期待出力を付けます。ヘルスチェックのパスと状態コードを含めます。
- 戻し方の発動条件、手順、データ互換性を定義します。フィールド追加を先に、削除を後に行うなど、前方・後方互換を保ちます。
- 全設定のキー、サンプル値、必須・既定値、注入元を示し、秘密情報をリポジトリへ入れません。
- 停止の要否、利用不可の時間帯、影響範囲、利用者へ通知する担当を記載します。
- 公開後のログイン、主要経路、重要な書き込み、ログとアラート送信など、5–10 件の必須スモーク項目を定めます。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 公開コマンドだけあればよい | 各段階の検証コマンド・期待値・戻し方が必要です。 |
| アプリだけ戻せばよい | データ互換と DB 変更の順序も定義します。 |
| 通知とスモークは公開後に考える | 影響時間帯、担当、5–10 件の検証項目を事前に決めます。 |

## Red Flags
- 環境と設定元、期待出力、ヘルスチェックが不明です。
- ロールバック条件・手順・データ互換性がありません。
- 停止・通知担当・必須スモーク項目が未定義です。
