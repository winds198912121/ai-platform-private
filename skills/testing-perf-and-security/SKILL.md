# 性能とセキュリティのテスト

## Overview
実負荷に近いモデルで性能を測り、再現できる条件と指標を記録します。権限逸脱、注入、認証攻撃、情報漏えい、アップロードとパスを検証し、修正後に同じケースを再実行します。

## When to Use
- 性能受入、容量の把握、負荷試験の原因特定、安全性テストと回帰検証。
- 対象外：機能ケース（testing-case-design）、カバレッジ・終了条件（testing-coverage-matrix）、公開後の継続監視と容量費用計画。

## Core Process
- 開始前に同時実行数、継続時間、P95 / P99、エラー率上限、許容する縮退を数値で定めます。数値目標がなければ実行しません。
- 実際に近い読み書き比率、データ分布、ログイン・セッション負荷を使い、段階的増加とスパイクの 2 パターンを実行します。
- スクリプト、引数、データ量、環境仕様、対象バージョンを記録し、どの条件でどの数値を得たかを結論に示します。
- スループット、エラー、遅延、資源の 4 指標を観測し、DB の低速クエリ、接続プール、GC、ロック待ちなどのボトルネックと対応を示します。
- 水平・垂直の権限逸脱、SQL / コマンド / テンプレート注入、弱いパスワード・総当たり、エラー・ログ・出力の機微情報、アップロードとパストラバーサルを検証します。
- 全失敗に再現手順、影響範囲、修正案を付け、同じケースが成功するまで回帰検証します。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 数値を見ながら目標を決める | 負荷条件と判定値を開始前に定めます。 |
| 単一負荷モデルで十分 | 実分布、認証負荷、段階負荷とスパイクを含めます。 |
| 修正したので安全性の再試験は不要 | 同じ失敗ケースの成功を確認します。 |

## Red Flags
- 数値目標、実際に近い負荷モデル、環境・バージョンの記録がありません。
- 4 指標とボトルネックの特定が不足しています。
- 権限逸脱・注入・認証攻撃・漏えい・アップロードの検証、失敗の再現と回帰がありません。
