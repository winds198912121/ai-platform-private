# BMAD v6 · UX 設計（create-ux-design）

## Overview
デザインシステム（トークン・共通テンプレート）を先に固め、各画面は機能 ID と 1 対 1 で定義します。網羅性はローファイで、重要画面だけハイファイで確認します。（BMAD Method v6 本家ワークフローの手順を本プラットフォーム向けに要約したもの。原典：docs.bmad-method.org）

## When to Use
- 画面・帳票 ID を持つ業務システムの UI を設計するとき。
- 現行画面（AS-IS）と新画面（TO-BE）を比較してレビューするとき。
- 対象外：UI の無いサービス、データ処理のみの案件。

## Core Process
1. 現行画面の型（検索条件 + 一覧 + 明細、ファンクションキー等）を抽出し、共通テンプレートとトークンにする。
2. 台帳の画面・帳票 ID ごとに、項目・桁数・必須・初期値・エラー時表示を表で定義する。
3. 全画面をローファイで出して漏れを確認し、業務上重要な画面だけハイファイ化する。
4. 状態（読込中・空・エラー・権限なし・閲覧のみ）を画面ごとに明記する。

## Common Rationalizations
| 言い訳 | 事実 |
|---|---|
| 「画面数が多いので代表画面だけ」 | ID と 1 対 1 でなければ網羅漏れを検出できない。ローファイで全件出す。 |
| 「見た目は開発で決める」 | プロトタイプで職員の確認を取らないと手戻りが開発後に出る。 |

## Red Flags
- 画面定義に画面 ID が無い、または台帳に無い ID がある。
- 権限による表示差（閲覧可・編集不可）が書かれていない。
- 共通テンプレートを使わず画面ごとにレイアウトがばらばら。

## Verification
- [ ] 台帳の画面・帳票 ID がすべて画面定義に対応している。
- [ ] 各画面に項目・桁数・必須・エラー表示がある。
- [ ] 状態（読込中・空・エラー・権限）が網羅されている。
- [ ] 重要画面のハイファイ版がレビュー済み。
