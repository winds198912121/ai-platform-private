# 要件番号と受入基準

## Overview
安定した要件・ストーリー・受入基準の番号を付け、条件と期待結果、対象範囲、依存、曖昧さを検証可能にします。

## When to Use
- 要件一覧、ユーザーストーリー、受入基準、範囲と依存の作成・レビューに使用します。
- 対象外：要件確定後の実装、アーキテクチャ・テスト・運用の技術設計。

## Core Process
- 各要件に安定した REQ-NN を付け、誰が・どの条件で・どの結果を期待するか明記します。
- ストーリーは US-NN とし、「<役割>として、<価値>のために<能力>がほしい」の形式で、対応する REQ を付けます。
- 各要件に最低 1 件の AC-NN を対応させ、数値・境界・発動条件により自動または人が再確認できるようにします。
- 「使いやすい」「高性能」など判定できない表現は禁止します。
- 今回の対象外（Out of scope）と、外部システム・データ・承認への依存を明示します。
- 対立と曖昧さを独立した節へまとめ、解釈候補と決定者を示します。実装者の推測で選びません。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 番号は後で付ける | 追跡と変更管理のために安定した番号が必要です。 |
| 良い体験という受入基準で十分 | 条件・数値・境界を使って再確認可能にします。 |
| 範囲の解釈は実装者に任せる | 対象外・依存・曖昧な点と決定者を明示します。 |

## Red Flags
- 要件番号がないか、ストーリーと REQ が対応していません。
- AC がなく、期待値・条件・境界で判定できません。
- 対象外・依存・対立の記録がありません。
