# Node.js 開発規約（依存なしの ESM）

## Overview
プラットフォームの実行形式は、依存なしの Node ESM と node:test です。exec.mjs が実際に実行する条件に従います。

## When to Use
- 依存なしの .mjs モジュールの作成・修正、node:test の追加、純粋関数・非同期処理のレビューに使用します。
- グローバル状態・時刻・乱数による不安定なテストや、イベントループの停止を調査するとき。
- 対象外：Java、Python、フロントエンドのビルド成果物。外部依存が必要な場合は先に設計上の許可を確認します。

## Core Process
- ESM の import / export を明示し、require を混在させません。1 ファイルは 1 責務で、公開関数を契約とします。
- 同一入力に同一出力を返し、グローバル状態、Date.now()、Math.random()、ファイルシステム、ネットワークは引数で注入します。
- Node の組み込みモジュールだけを使用し、必要な状態・保存先はメモリ内の純粋なデータ構造で扱います。
- エラーは { ok: false, code, message } または独自のエラー型で明示し、握り潰しません。
- 非同期処理は await またはコールバックに統一します。独立処理は Promise.all、依存する処理は順次 await とし、偶然の実行順に依存しません。
- 大きなループは分割またはストリーム化します。同期 IO は起動時に一度だけ実行する処理に限定します。
- 時刻と ID 生成器を注入します。金額は最小単位の整数または BigInt を使用し、浮動小数点は表示用途に限定します。
- node:test + node:assert/strict で、各公開関数の正常系・境界（空、0、極値、重複）・エラーを具体値で検証します。
- 許可された外部依存がある場合はバージョンと lockfile を固定し、postinstall を禁止し、engines に Node の対応バージョンを記載します。

## Common Rationalizations
| よくある説明 | 確認すべき事実 |
|---|---|
| 慣れているので require と import を混在させる | ESM に統一し、公開契約を明確にします。 |
| 時刻・乱数・ネットワークは直接使う | 注入しなければ実行とテストの再現性が失われます。 |
| catch して続ければよい | エラーを明示し、失敗分岐を検証します。 |
| 重い同期処理でも単体テストは通る | イベントループを止めない構造が必要です。 |
| ライブラリを気軽に追加する | 実行側は組み込みだけです。依存を追加する前に設計・バージョン・lockfile を確認します。 |

## Red Flags
- require と import の混在、未登録依存、モジュール単位の可変状態があります。
- 直接の時刻・乱数・IO、握り潰す catch、実行順への依存があります。
- イベントループを止めるループや通常処理中の同期 IO があります。
- テストが具体値や境界・エラーを検証していません。
