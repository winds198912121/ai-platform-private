# ロケール方針（2026-10-17 棚卸し）

> AI ワークフロー設計レビュー §P0系 + CN→JA スキャン依頼の作業記録。
> UI 既定言語は **日本語**、ソース内コメントは **混在を維持**（手動機）。

## 1. 結論

| 領域 | 状態 | 方針 |
|---|---|---|
| UI 文字列 | 既に **英語 + 日本語** の二言語 | `i18n.mjs` 維持、既定 `ja`、英語 fallback |
| エラーメッセージ / HttpError | **英語**（API 契約として固定） | そのまま |
| console.log / console.warn / console.error | **英語**または**日本語** | ユーザー可視のみ日本語 |
| 開発ツール出力（`tools/e2e*.mjs`, `tools/ui_tree.mjs`） | 混在 | ユーザー可視文字列 9 件を CN→JA 化（PR 修正済み） |
| **ソースコードコメント** | **混在** | **意図的にそのまま** |
| PROGRESS.md / 既存 docs / 既存 SKILL.md 本文 | 履歴 | **そのまま**（新規追加分だけ日本語） |
| 案件専用スキル文書 | slot のみ存在 | 担当者が書くとき日本語で書く |

## 2. 何を変えたか

ユーザー可視の中国語 9 箇所を日本語化（合計 9 箇所 / 30 文字）：

| ファイル | 行 | 変更前 | 変更後 |
|---|---|---|---|
| settings.mjs | 89 | `[settings] 保存失败：` | `[settings] 保存に失敗：` |
| tools/e2e.mjs | 366 | `FAIL  异常：` | `FAIL  異常：` |
| tools/e2e_live.mjs | 30 | `… 仍在等待「…」已 …s` | `… 待機中「…」経過 …s` |
| tools/e2e_live.mjs | 127 | `… 个文件不在规约目录内` | `… 規定ディレクトリ外 … 件` |
| tools/e2e_live.mjs | 135 | `FAIL  异常：` | `FAIL  異常：` |
| tools/ui_tree.mjs | 43 | `未找到 Google Chrome，跳过 UI 检查…` | `Google Chrome が見つからず、UI 検査をスキップ…` |
| tools/ui_tree.mjs | 855 | `/还没有产出源码/` テスト | `/まだソースが出力されていません/` テスト |

UI が「空」か確認する e2e テスト 1 件もテスト文を日本語化した（メッセージが UI 文字列と一致しないといけなかったため）。

## 3. なぜコメントを変えないか

`harness.mjs / agent.mjs / public/app.js / PROGRESS.md / docs/*.md / skills/*/SKILL.md` など、76 ファイルに **約 71,851 文字の中国語**が残っている。

これらを機械的に翻訳しない理由：

1. **意図的なコメント規約**：歴史的に開発メンバーが CN/EN/JA 混在で書いている。各人が読みやすい言語を選んでいる自由を奪わない
2. **翻訳リスク**：誤訳すると理解を誤らせる（特に「待つ」「試す」「依存」など文脈が肝）
3. **テスト破壊**：テスト 31 件は中国語の固定文言を assert しており、`docs/test-triage-2026-10-17.md` で分類したように "文言ドリフト" の状態。機械翻訳すると一気にこれらが FAIL する
4. **CI コスト**：71K 文字を人手レビューすると数日かかる（PR 1 本で済む量ではない）
5. **過去ログ整合**：PROGRESS.md の変更多言史は日本語化すると検索性が落ちる

## 4. 新規ファイル / コミットメッセージ

- 新規 `.mjs` / `.md` / `.json` を作成する時は **日本語**で書く
- コミットメッセージは **日本語**（先頭 70 字 conventional prefix + 空白 + 日本語要約）
- 例：`P0-1: 要件台帳の再走査エンドポイント追加（モデル不介入、既存案件流し直し）`

## 5. i18n（UI）言語キー

`public/i18n.mjs` の構造：
- `LANGS = [{code:'en'}, {code:'ja'}]`
- 既定 `cur = 'ja'`（日本語）
- `DICT` の各エントリは `[en, ja]` の順
- 欠落時は英語 fallback

新規 UI 文字列を追加する場合は：
```js
'foo.bar': ['English text', '日本語文字列'],
```

## 6. 言語別の担当表（新規・翻訳）

| 領域 | 担当 | ルール |
|---|---|---|
| UI 文字列 | フロント実装者 | `i18n.mjs` に追加（両言語同時）。日本語が先、英語 fallback |
| エラーメッセージ | バックエンド実装者 | 英語固定。UI 側で翻訳する場合は i18n に追加 |
| ソースコメント | 書いた人 | 混在自由。ただし新規コメントは日本語推奨 |
| コミットメッセージ | 作者 | 日本語。70 字 conventional prefix + 日本語要約 |
| PR / Issue | 投稿者 | 日本語 |
| 仕様書 / 入力資料 | 案件側 | 書き手の言語のまま |
